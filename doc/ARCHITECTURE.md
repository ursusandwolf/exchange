# Архитектура учебного проекта: Crypto Exchange Simulation (Spring Boot)

Этот проект представляет собой упрощенную симуляцию централизованной криптовалютной биржи (CEX), построенную на стеке **Java 17 + Spring Boot 3 + JPA**.

## 2. Роль Spring Boot в проекте

Spring Boot здесь — это "клей", который связывает разрозненные Java-классы в работающее приложение.

### А. Dependency Injection (DI)
Мы используем **Constructor Injection** через аннотацию Lombok `@RequiredArgsConstructor`. 
Spring автоматически находит классы, помеченные `@Service` или `@Repository`, создает их экземпляры и передает в нужные места.

*Пример:* `OrderController` получает `ExchangeService` автоматически.

### Б. Управление транзакциями (`@Transactional`)
Это критическая часть для финтеха. Операция матчинга ордера включает несколько шагов:
1. Загрузка кошельков из БД.
2. Резервирование средств.
3. Проведение сделок в движке.
4. Обновление балансов в БД.

Аннотация `@Transactional` гарантирует, что если на шаге 4 произойдет сбой, все изменения балансов (шаг 2 и 3) будут **откачены (Rollback)**, и деньги пользователей не пропадут.

### В. Spring Data JPA
Мы не пишем SQL-запросы вручную. Мы описываем сущности (`@Entity`) и интерфейсы (`JpaRepository`).
*   **Hibernate** автоматически создает таблицы в H2/PostgreSQL.
*   **EntityManager** следит за состоянием объектов и синхронизирует их с БД.

## 3. Описание ключевых сущностей

| Сущность | Описание |
| :--- | :--- |
| **User** | Владелец аккаунта, связан с кошельком (1:1). |
| **Wallet** | Хранит Map балансов. Использует `@ElementCollection` для связи с таблицей БД. |
| **Order** | Заявка. Хранится в БД для истории и восстановления. |
| **OrderBook** | "Стакан". Хранится **в памяти** (In-Memory) для максимальной скорости сведения. |
| **MatchingEngine** | Чистый алгоритмический движок (Pure Logic), не знающий о базе данных. |

---

## 4. Жизненный цикл ордера (Data Flow)

1.  **Request**: Пользователь отправляет POST запрос на `/api/orders/submit`.
2.  **Controller**: `OrderController` принимает параметры и вызывает `ExchangeService`.
3.  **Transaction Start**: Spring открывает транзакцию.
4.  **Validation**: Проверка баланса в БД.
5.  **Matching**: Поиск встречных ордеров в `OrderBook`.
6. Settlement: Если сделка найдена, `ExchangeService` вызывает `Wallet.credit/debit`.
7. Persistence: Сохранение обновленных сущностей через `userRepository.save()`. Для прямых начислений (например, через админ-панель или инициализатор) используется метод `deposit(userId, asset, amount)`, гарантирующий запись в БД.
8. Transaction Commit: Если ошибок нет, данные фиксируются в БД.

## 5. Безопасность (Security)

В проекте реализована многоуровневая система безопасности:
*   **JWT Authentication**: Доступ к API защищен Bearer-токенами.
*   **BCrypt Hashing**: Пароли пользователей хранятся в зашифрованном виде.
*   **Validation**: Входящие данные проверяются через Jakarta Validation (`@Valid`).
*   **Data Masking**: Использование DTO (Records) предотвращает утечку внутренней структуры БД.
*   **Global Exception Handling**: Централизованная обработка ошибок исключает StackTrace в ответах.

## 6. Надежность и Целостность (Reliability)

*   **Transaction Integrity**: Синхронизация между БД и In-Memory состоянием. Изменения в стакане (`OrderBook`) применяются только **после успешного коммита** транзакции в базу данных через `TransactionSynchronizationManager`.
*   **State Recovery**: При старте приложения выполняется автоматическое восстановление стаканов (`@PostConstruct`) на основе активных ордеров из БД.
*   **Thread Safety**: Использование `ConcurrentHashMap` и `ConcurrentSkipListMap` для потокобезопасной работы в многопоточной среде Spring Boot.
